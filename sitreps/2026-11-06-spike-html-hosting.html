Sitrep: spike-html-hosting

2026-11-06 · covering 2026-11-03 to 2026-11-06 · goal experiment.html.spike-html-hosting · six of eleven tasks shipped

spike-html-hosting asks what Standards Lab's GitHub Pages sites and its hosted, persistent artifacts look like when published as native web on experiment.html's stack. Three JaimeStill project sites stand in for the organization: this one for org, one for the architecture repository, and one for sqlate's docs/ guide. This entry is for a reader catching up on the spike: what its first six tasks shipped, what they decided, and what comes next.

In short

  • Three Pages project sites build with Vite and deploy from their own workflows, each under its /<repository>/ base, and every one passes a check that no CSS module script is left in its build, so Safari loads every page.
  • The architecture repository's 29 pages and sqlate's README and docs/ guide render from pinned, byte-for-byte Markdown copies at build, with their front matter, resolved links, and code highlighted in each palette's own editor theme.
  • Every file the sites share lives in one SDK released by tag, spike-html-hosting-sdk, whose template a new site is scaffolded from with one command.
  • Every page carries its navigation from one components layer released by tag: the site nav, the page header, the section tree with H and L, and the site index in a Pages drawer; the reader's theme carries across the three sites on their shared origin.

What shipped

layers

PR #1, merged 2026-11-03. Four repositories: this root as the org stand-in, the architecture and sqlate stand-ins, and spike-html-hosting-components, the layer the components task filled. Each site's base is read from its package name, so a copied site changes only its name and its text. Each site's Pages workflow runs the full check on a push to main before it deploys, and its CI runs the same check on pull requests. The check that no CSS module script is left in a build is ESLint over the build output, proven on six leftover forms and on clean look-alikes.

content

PR #2, merged 2026-11-04. The architecture site renders its 29 front-matter pages, copied at 8706d04, and sqlate its README and docs/ at v0.6.1, each Markdown file a page Vite builds like a file, with no generated files in the tree. Each copy stays byte for byte, held to a record of its source's git blob hashes by a unit test. A .md link becomes its page's link, a link to a file not copied goes to github.com at the pin, and the build fails on any other relative link. A crawl of every page checks each link and fragment. The architect's review redirected the shell: the theme menu now offers every profile, T opens it, and main is a centered reading column.

screenshots

PR #3, merged 2026-11-04. mise run screenshots on every site, through spike-html-apps-tooling's capture bin: every built page, named by its path, whole, at 1280 and 390 wide, light and dark, and split across runs with --page. A test in each site's check runs it and fails if it leaves a capture file behind.

template

PR #4, merged 2026-11-04. spike-html-hosting-sdk v0.1.0 replaced the hand copies across the sites: the Vite plugins, the lint configuration, site.css, the content check, the shell checks, the crawl, the capture description, the currency bin, and reusable Pages and CI workflows. Its release carries a template, and pnpm dlx github:JaimeStill/spike-html-hosting-sdk#v0.1.0 <repo> scaffolds a new site from it. The three sites adopted it by scaffolding into a scratch directory and copying over, keeping their notes, history, and copied trees. One mistake is on the record: the SDK's first pull request merged with its CI red, its failing exit hidden by a pipe; no tag was cut, and a fix-forward release went out green.

highlighting

PR #5, merged 2026-11-05. SDK v0.2.0 highlights code at build with Shiki 4.6.0, with no script on the page. Each palette's code takes the colors of the editor theme the palette comes from, light and dark: Flexoki's own VS Code themes, its green moved to the foundation's hue 142°, and Shiki's bundled primer, catppuccin, and everforest. A site appends a theme for an outside palette. A browser check fails a palette whose code isn't recolored to its theme.

components

PR #6, merged 2026-11-06, with spike-html-hosting-components #3 to #6 and spike-html-hosting-sdk #4 and #5. Components v0.1.0 through v0.2.2 and SDK v0.3.0 and v0.3.1 were released, and the three sites pin SDK v0.3.1 and components v0.2.2. Every page now has the site nav across the three sites, a page header from its front matter, a section tree with reading progress and H and L moving between sections, and a site index that docks as a column where it fits and is a Pages drawer, opened by P, where it doesn't. The SDK's checks now hold every page to no sideways scroll at 390px, no navigation word broken mid-word, main centered and directly under the header, and a keys help dialog that lists every binding. Two of the faults these checks now catch had passed the earlier reviews; the architect found them by viewing the local builds at checkpoint 2.

What was decided

  • Project sites under /<repo>/. The spike publishes only on its own JaimeStill repositories, with pinned copies and their provenance; a standards-lab.github.io root site stays a sourced option.
  • Markdown stays Markdown. Architecture pages and repository docs are authored in Markdown and rendered at build; HTML is for persistent artifacts.
  • One SDK by tag, not a template repository. A fix reaches a site with a tag bump; the template ships inside each release, and its workflows are called at the same tag.
  • Each palette's code is true to its source theme. One theme bound to the foundation's sixteen color tokens got only 24 to 69% of characters right, so syntax colors stay out of the foundation, in the SDK's palette-to-theme mapping.
  • H and L move between sections. Bound arrow keys took over sideways scrolling in code and tables and ignored the keys module's off switch, so the arrows stay the browser's.
  • A side column docks only where it fits. Where a column would be narrower than 16rem beside main's 80ch, the site index is a drawer and the section tree a sticky bar.
  • Rolling currency. Every repository sets pnpm's minimum release age to 0 and reads each release's notes before its bump lands, in place of a one-day wait.
